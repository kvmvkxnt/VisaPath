# 0005. Protobuf bytes on Redis Streams

Date: 2026-11-08. Status: accepted.

## Context

Events reach `ingest` as protobuf over gRPC. `ingest` then puts them on a
Redis stream for `detector`, and `detector` puts alerts on another stream for
`web`. Stream entries could carry JSON or the protobuf bytes.

## Decision

Each stream entry has one field, `pb`, holding the serialized protobuf
message (`Event` or `Alert` from `proto/`). Consumers decode with code
generated by `buf`.

## Consequences

- One schema for every hop. `buf breaking` in CI catches incompatible changes
  before Go, Python and TypeScript drift apart.
- `ingest` forwards bytes it already has; no re-encoding.
- Entries are unreadable in `redis-cli`. Debugging needs a small decode
  command, which ships with `ingest`.
